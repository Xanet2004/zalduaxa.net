# Local Quality Tooling

Local code quality workflow using SonarQube, JaCoCo, and Homepage.

[Back to menu](/README.md)

---

## What's included

| Tool | Role | Access |
|------|------|--------|
| SonarQube | Central quality dashboard — code smells, bugs, vulnerabilities, coverage, technical debt | `http://localhost:9000` |
| JaCoCo | Java test coverage report (HTML + XML) | `backend/target/site/jacoco/index.html` |
| Quality runner | Frontend Playwright + axe + Lighthouse automated checks | `http://localhost:9102/metrics` |
| Homepage | Local tools dashboard with links to all services | `http://localhost:3001` |

---

## How to start

### Full quality stack

```bash
docker compose -f docker-compose.quality.yml up -d
```

This starts SonarQube, its database, and the frontend quality runner.

### SonarQube only

```bash
docker compose -f docker-compose.quality.yml up -d sonarqube-db sonarqube
```

Requires `vm.max_map_count >= 262144` on the host. Check with:

```bash
sysctl vm.max_map_count
```

### Quality runner only

```bash
docker compose -f docker-compose.quality.yml up -d quality-runner
```

### Homepage

```bash
docker compose -f docker-compose.tools.yml up -d
```

## Generate coverage data

Backend JaCoCo coverage is generated by the Maven `verify` phase:

```bash
cd backend
./mvnw clean verify
cd ..
```

Expected output files:

```text
backend/target/site/jacoco/jacoco.xml       # XML report for SonarQube
backend/target/site/jacoco/index.html       # Human-readable HTML report
```

## Run the SonarQube scanner

### 1. Export your token (never commit it)

```bash
export SONAR_TOKEN='your-local-sonarqube-token'
echo ${#SONAR_TOKEN}    # should print a number greater than 0
```

Generate the token from SonarQube UI → User menu → My Account → Security.

### 2. Run the scanner

```bash
docker run --rm --network host \
  -v "$(pwd):/usr/src" \
  sonarsource/sonar-scanner-cli \
  -Dsonar.host.url=http://localhost:9000 \
  -Dsonar.token="$SONAR_TOKEN"
```

If the scanner fails with an authentication error about `sonar.login`, use this instead:

```bash
docker run --rm --network host \
  -v "$(pwd):/usr/src" \
  sonarsource/sonar-scanner-cli \
  -Dsonar.host.url=http://localhost:9000 \
  -Dsonar.login="$SONAR_TOKEN"
```

The scanner reads `sonar-project.properties` from the repository root automatically.

## Analysis scope

The current `sonar-project.properties` configures a single SonarQube project for the monorepo:

| Source | Coverage |
|--------|----------|
| Backend Java (`backend/src/main/java`) | JaCoCo XML (`backend/target/site/jacoco/jacoco.xml`) |
| Backend tests | Measured by JaCoCo, included in coverage |
| Frontend TypeScript (`frontend/src`) | Static analysis only |
| GitHub Actions workflows (`.github/workflows`) | Static analysis only |

### Explicitly out of scope

- **Frontend test coverage** — intentionally postponed because no frontend tests exist yet.
- **GitHub Actions CI integration** — intentionally postponed. Local SonarQube is not reachable from GitHub-hosted runners. CI integration will be added after deciding on a self-hosted runner or secure network exposure strategy.

---

## Security notes

- **Never commit tokens.** `SONAR_TOKEN` must be exported in the shell and never written to tracked files.
- **Do not expose SonarQube or Homepage publicly** without proper authentication and HTTPS.
- **Generated files** (`.scannerwork/`, `target/`, `dist/`, `node_modules/`) are gitignored and must never be committed.
